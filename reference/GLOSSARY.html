agentic_uav — Glossary

Canonical vocabulary for the swappable UAV-swarm simulator. Adhere to these terms in every lesson.

Read this first. A sector here is a single grid cell, not a region. There is no A* and no region sweep — movement is one Manhattan step per tick. The thesis lives or dies on two invariants defined below: observation symmetry and decentralization.

World & State

Sector
One grid cell. Holds coverage (0.0–1.0), priority ("normal"/"urgent"), blocked, plus hazard/visibility/comm_quality fields. models.py
Cell
A tuple[int, int] coordinate — the key type for the sector grid. models.py
WorldState
width, height, and sectors: dict[Cell, Sector]. The central ground truth — written for sensing and metrics, but no decision path reads its dynamic state. models.py
UavState
Per-UAV runtime: cell, role, energy, health, target_cell, inbox, active. Method-agnostic — the world and GUI never branch on a method. models.py
role
One of coverage, priority_responder, relay. Part of the shared action schema so methods compare fairly.

Belief & Observation

BeliefMap
A UAV's local knowledge: covered, known_urgent, cleared_urgent, peer_intents. Lives on MethodState.beliefs, not on UavState — that's what keeps the world model method-agnostic. planning.py
Observation
The per-UAV input every method receives: self, nearby sectors, known_urgent (from belief), messages. Built once per UAV by ObservationBuilder.build() and handed to whatever method is running. planning.py · types.py
Observation symmetry (invariant)
All five methods get the identical observation for a given UAV. Layout is global ("UAVs have a map"); coverage/urgent are discovered locally. Methods differ only in reasoning. The removal of the old global urgent_cells list is what enforces this. ADR-0001
Decentralization (invariant)
Every method decides per-UAV from local observation + belief + peer messages + onboard state. No global oracle, no central planner — including the LLM method. ADR-0001 · design spec

Decision Layer

SwarmMethod
The interface every method implements: initialize_mission(), decide_tick(), handle_event(). policy.py
The 5 methods
static (A, pre-mission partition), rules (B, rule-adaptive), task_consideration (C, task-bidding; after Chen 2023), greedy (D, nearest-urgent/uncovered heuristic), and agentic (the proposed LLM method). All in policy.py; selected by build_method(name).
greedy
A baseline — the renamed former AgenticMethod heuristic. Also the universal fallback when LLM output is invalid. Not the contribution.
agentic
The proposed method. LLM-driven, event-triggered re-plan, consumes and emits intent_summary, falls back to greedy on invalid output.
Action / MethodState
An Action bundles target_cell, new_role, messages. MethodState carries per-method memory (assignments, beliefs, peer intents, replan flags). planning.py

LLM Seam

AgentDecider
Provider-agnostic protocol: decide(observation) -> action JSON. The pipeline is serialize → call → validate → fallback. llm_agent.py
MockAgentDecider
Default, deterministic, dependency-free. Currently mirrors greedy, so a real agentic-vs-baseline number needs a vendor. llm_agent.py
Provider adapters
Real Bedrock / QGenie deciders, opt-in via the llm extra (boto3). llm_providers.py
build_decider(name)
Factory selecting mock (default) / bedrock / qgenie, via arg or AGENTIC_UAV_DECIDER env var. llm_agent.py

Harness

Simulation.step()
One tick: apply events (→ handle_event) → deliver messages → build observations → decide_tick → resolve actions → drain energy → sense → log. simulation.py
NetworkModel
The only peer-information path: range-limited, delayed, TTL-bounded message delivery. communication.py
EventInjector / event
Scheduled disruptions (dropout, block_sector, urgent_sector, …) that mutate the world and trigger re-plans. simulation.py
MetricsLogger
Records coverage ratio, active UAVs, messages, and the replan_count / plan_change_count traces used for the recovery analysis. simulation.py

New / WIP modules (on disk, not all wired)

agent_core.py
Richer per-UAV context (LocalWorldModel, SectorBelief, HealthStatus, …) — groundwork toward the spec's full agent.
tools.py
Tool functions for agent reasoning (tool_find_best_task, tool_assess_hazards, …).
safety.py
SafetyGovernor: energy/geofence checks, failsafe fallback.
environment.py
BlackoutZone for comm-blackout scenarios.
