Lesson 4 — agentic_uav

The LLM seam

Where the contribution plugs in — and why it's a swappable adapter with a deterministic mock, not a hard dependency.

Mission link. The agentic method's intelligence is pluggable. The seam is real and tested today; the LLM itself is a drop-in. That single fact does double duty: it enables a clean, fair evaluation and it is the honest reason there's no measured win yet. By the end you can describe the contract, the fallback, and the caveat without hedging.

A. Recall: where agentic plugs in

From L2, agentic is selected in exactly one place (build_method), and decide_tick is the only tick beat that differs between methods. Everything below opens what that one beat does — and shows the contribution never widens the seam.

B. The contract: AgentDecider

The whole contribution sits behind one tiny, provider-agnostic protocol. JSON dict in, action dict out; the caller — not the decider — validates.

# llm_agent.py:26 — the entire seam, in four lines
@runtime_checkable
class AgentDecider(Protocol):
    def decide(self, observation: dict[str, Any]) -> dict[str, Any]:
        ...
in: observation
A JSON-only local view (see D). No live objects, no world handle.
out: action dict
A {target_cell, role, ranked_targets}-shaped dict — proposed, not trusted.
who validates
The caller, against the world. The decider is never granted authority over the move.

C. Selecting a backend: build_decider

One factory chooses the backend by the name argument, else the AGENTIC_UAV_DECIDER env var, else the default "mock". Real providers are imported lazily, so importing llm_agent never drags in boto3 or urllib.

# llm_agent.py:47 — default is mock; tests & sweeps stay offline
choice = (name or os.environ.get("AGENTIC_UAV_DECIDER") or "mock")...
if choice == "mock":    return MockAgentDecider()
if choice == "bedrock": from ... import BedrockAgentDecider  # lazy
if choice == "qgenie":  from ... import QGenieAgentDecider   # lazy
One branch, by design. This factory is the only place that branches on backend. method_name still selects the method (L2); the env var only selects which decider the agentic method drives. The swappability invariant is untouched.

D. The decision pipeline

Every per-UAV decision flows through decide_proposal() (llm_agent.py:124). It is four steps, and the last one is a safety floor.

  1. Serialize the observation to a JSON-only local view. serialize_observation, llm_agent.py:63
  2. Call the decider with that dict. decider.decide(...) — mock or vendor
  3. Validate the raw output against the world. validate_action, llm_agent.py:105
  4. Fall back to greedy_decision on any failure. the L2 baseline, as a floor
# llm_agent.py:137 — the load-bearing shape
try:
    raw = decider.decide(serialize_observation(observation))
    validated = validate_action(raw, simulation)
except Exception:
    validated = None
if validated is None:
    return greedy_decision(...), []   # ← safety floor

Serialize emits only local keys. Note what is absent: there is no urgent_cells. The decider literally cannot see global state — this is L3's observation symmetry, enforced at the wire.

# llm_agent.py:63 — the ONLY keys the decider ever receives
return {
  "self": ..., "nearby": ..., "known_urgent": ...,
  "messages": ..., "peer_intents": ...,
}   # no "urgent_cells", no world scan, no oracle

Validate is strict (llm_agent.py:105). Three checks, then normalize or reject:

  1. → Must be a dict; role must be in ALLOWED_ROLES (:111).
  2. → target_cell must be in-bounds and not blocked (:114).
  3. → ranked_targets filtered to in-bounds / unblocked cells (:116).
  4. → Returns normalized {target_cell, role, ranked_targets}, else None.

So three distinct failure modes — (a) the decider raises, (b) invalid / non-JSON / wrong shape, (c) target blocked or out of bounds — all route to greedy_decision. That is the "falls back to greedy on invalid output" promise, made concrete and total.

E. The mock: a deterministic greedy mirror

The default MockAgentDecider (llm_agent.py:179) is deterministic and dependency-free. Its core logic (:196) prefers the nearest believed-urgent cell, else the nearest uncovered, sorted by Manhattan distance, using _prefer_unclaimed() to steer off peer-claimed targets — then returns target_cell, role, reason, and ranked_targets. Its docstring states the intent plainly:

# llm_agent.py:180 — the mock's docstring
"Deterministic, dependency-free decider that mirrors the greedy
 heuristic. Under this mock, `agentic` behaves like `greedy` while
 exercising the full serialize -> validate -> action pipeline.
 Swapping in a real LLM adapter is the only change needed for a
 genuine evaluation."
The plumbing is exercised today. Even with the mock, the full pipeline — serialize, validate, fallback, and in-tick negotiation — runs and is tested. Swapping a vendor changes nothing else: same protocol, same validation, same deconfliction. The seam is proven before any API key exists.

F. Event-triggered re-plan + in-tick negotiation

The AgenticMethod wiring lives in policy.py:211. __post_init__ defaults the decider to MockAgentDecider (:216). It is the only method that arms a replan up front: initialize_mission returns MethodState(replan_pending=True), and handle_event (:225) sets replan_pending=True — that is the event-triggered hook (mission start, plus dropout / urgent_sector / block_sector). Re-plan cadence is event-triggered, not every tick (ADR-0003).

# policy.py:241 — replan when armed, else execute the persisted plan
if method_state.replan_pending:
    actions = self._replan(...)        # decide_proposal per UAV, collect ranked, log replan
    method_state.replan_pending = False
else:
    actions = self._execute_plan(...)  # run plan, emit intent_summary

Negotiation settles ties synchronously, in one tick (ADR-0002). When two UAVs propose the same target, _deconflict (:286) gives it to the nearest (lexicographic id breaks the tie); the loser goes to _repick (:323), which tries its next-best ranked target, else falls back to greedy_decision. The ranked_targets the decider returned are what make graceful deconfliction possible without a central planner.

G. The real providers, briefly

Two vendor adapters exist behind the same protocol (llm_providers.py):

AdapterSurfaceWhere
BedrockAgentDeciderAWS Bedrock Converse API, forced tool use; model from BEDROCK_MODEL_ID; lazy boto3.268–352
QGenieAgentDeciderOpenAI-compatible chat-completions over urllib; provider::model ids; tools opt-in via QGENIE_USE_TOOLS.355–452

The prompt itself preserves symmetry. build_prompt() (:120) enumerates only the candidate cells this UAV may legally target and instructs the model: "Do NOT invent coordinates." No global state is ever placed in the prompt, and validation is centralized in validate_action for every provider — so a vendor swap cannot quietly widen what the agent sees.

Honest caveat — say this out loud. Because the default decider is the greedy mirror, today agentic ≈ greedy and there is no measured advantage yet. The regression test test_mirrors_greedy_choosing_uncovered_when_no_urgent (tests/test_llm_agent.py:153) pins exactly this. The defense today is about architecture — a real, tested, fair, swappable seam — not a number. Wiring a vendor is the single remaining change for a genuine evaluation (we pick that up in L6).

Defense drill — let's rehearse aloud, then check

Read the likely objection, say how we'd answer, then reveal the version we've been refining. Us pressure-testing our own argument before a reviewer does.

Attack 1: "If the LLM hallucinates a blocked cell, doesn't that corrupt the comparison?"

validate_action rejects any target that is out-of-bounds or blocked (and filters ranked_targets the same way). A rejected action returns None and the move falls back to greedy_decision. Bad output can never produce an illegal move — the world never executes an unvalidated proposal.

Attack 2: "Isn't 'agentic falls back to greedy' just admitting it's greedy?"

Fallback is a safety floor for invalid output. With a real decider, valid outputs drive behaviour and only malformed ones fall through. With the mock, yes — it mirrors greedy by design, because the mock is the plumbing test, not the experiment. Those are two different claims; don't let them be conflated.

Attack 3: "Does the LLM get more information than the baselines?"

No. serialize_observation emits the same local-only keys every method's observation exposes — self, nearby, known_urgent, messages, peer_intents, and notably no urgent_cells. The prompt then enumerates only legal candidate cells and forbids inventing coordinates. The agent sees strictly less, never more (ties to L3).
