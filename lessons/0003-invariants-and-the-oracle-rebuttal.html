Lesson 3 — agentic_uav

The two invariants & the oracle rebuttal

The fairness ADR in code: where the global oracle was deleted, and how to answer the question that can sink the thesis.

Mission link. This is the lesson that most directly arms the defense. The single most dangerous reviewer question is "isn't the agentic advantage just a global oracle?" If you can't answer it crisply, the headline claim is unfalsifiable — and a careful reviewer knows it. By the end you'll have a code-grounded, three-sentence rebuttal you can deliver cold.

Recall: the two invariants

From L1, the architecture protects two properties. Said precisely:

Observation symmetry. All five methods get the identical per-UAV observation. They can differ only in reasoning, never in what they see.
Decentralization. Every method decides per-UAV from local view + belief + peer messages + onboard state. No central planner, no global oracle.

These two are joined at the hip: symmetry says everyone sees the same thing; decentralization says that thing is local. Today we see how the code guarantees the second half — because that's where the oracle would hide.

The leak that used to exist

ADR-0001 is unusually candid about a real bug in the earlier code. The old ObservationBuilder injected a global list of every urgent sector, and the planning helpers scanned the whole world map. In the ADR's own words:

# ADR-0001, "Context"
"ObservationBuilder.build injected a global urgent_cells list (every urgent
 sector, regardless of where the UAV was), and the planning helpers
 nearest_open_urgent / nearest_uncovered scanned the entire world.sectors
 dictionary directly. That gave every method a global oracle over dynamic
 state, which made the agentic-vs-baseline comparison invalid: any
 'agentic' advantage could just be the oracle, not the reasoning."

Read that last clause twice. The authors identified that their own headline claim was unfalsifiable under the leaky design, and fixed it. That candor is the defense.

Where it was deleted — and what replaced it

Open planning.py and look at what ObservationBuilder.build emits today. The global urgent_cells key is gone; in its place, known_urgent is read from this UAV's own belief:

# planning.py:66 — the per-UAV observation, post-fix
observations[uav_id] = {
    "self":         uav,
    "nearby":       nearby,              # only sensed neighbourhood
    "known_urgent": sorted(belief.known_urgent),   # ← from THIS uav's belief
    "messages":     list(uav.inbox),
}
# No "urgent_cells". No world-wide scan. The dict cannot leak global state.

And belief only grows two ways — both local:

# planning.py:74 — _fold_into_belief: belief grows ONLY from sensed nearby sectors
for sector in nearby:
    if sector.coverage >= 1.0: belief.covered.add(sector.cell)
    if sector.priority == "urgent": belief.known_urgent.add(sector.cell)

# policy.py:512 — _ingest_messages: belief also grows from peer messages (range-limited)
if message.message_type == "urgent_sector":
    belief.known_urgent.add(target)

So a UAV knows an urgent sector exists only if it sensed it, or a peer's message reached it through the range-limited NetworkModel. There is no third path. That is decentralization made structural, not promised in a comment.

Why belief lives on MethodState, not UavState

A subtle but defensible choice (ADR-0001, "Consequences"): belief is stored on MethodState.beliefs, not on UavState.

If belief were on…Consequence
UavStateA decision-method concept leaks into the world model and the GUI — breaking the "simulator has no method-specific branch" invariant from L2.
MethodState ✓The world stays method-agnostic; ground truth lives in WorldState for sensing/metrics only, and no decision path reads it.

This is how the two invariants reinforce each other: keeping belief out of the world is what lets the harness stay method-blind (L2) and keeps dynamic state local (L3).

It's enforced by tests, not honour

Two tests turn the principle into a tripwire. The first is a structural regression guard:

# tests/test_llm_agent.py:45 — symmetry regression test
def test_serialized_observation_omits_global_state(self):
    serialized = serialize_observation(build_observation(simulation))
    self.assertEqual(set(serialized),
        {"self","nearby","known_urgent","messages","peer_intents"})
    self.assertNotIn("urgent_cells", serialized)   # the oracle stays dead
The behavioural pair — your strongest exhibit. Two tests in tests/test_simulation.py bracket the whole argument:
  • test_rules_ignore_far_urgent_work_without_local_observation_or_message (line 255): a UAV at (0,0) with sensing_radius=1 and an urgent sector at (4,4) does not target it — it cannot, because it never sensed it and got no message. (Proves: no oracle.)
  • test_rules_use_inbox_urgent_message (line 275): the same far urgent sector does get acted on once a peer's urgent_sector message arrives. (Proves: discovery works, but only through the legitimate channel.)
Ignorant without a signal; informed with one. That pair is the falsifiability argument, executable on demand.

Defense drill — let's rehearse our rebuttals

Read the likely objection, say how we'd answer it out loud, then reveal the version we've been refining. This is us pressure-testing our own argument before it meets a reviewer — not an exam.

Attack 1: "Isn't the agentic advantage just a global oracle?"

The global urgent_cells list was removed from ObservationBuilder; each UAV's observation now carries only known_urgent drawn from its own BeliefMap, which grows solely by sensing its neighbourhood or by range-limited peer messages. A regression test asserts urgent_cells is absent, and a behavioural test shows a far UAV with no signal never targets a distant urgent sector. So no method — agentic included — can see global dynamic state.

Attack 2: "Fine, but maybe agentic gets a richer observation than the baselines."

No — the observation is built once per UAV by a single ObservationBuilder and handed to whichever method is running; the builder doesn't know the method name (see L2's swappability invariant). All five methods receive byte-identical observations. They differ only in the reasoning applied to that shared input.

Attack 3: "Storing belief sounds like you bolted state onto the UAV to help agentic."

Belief lives on MethodState.beliefs, not on UavState — precisely so the world model and GUI stay method-agnostic. Every method gets the same BeliefMap machinery; greedy and rules use it too. It's shared infrastructure, not an agentic-only crutch.

Attack 4: "A UAV missing a far urgent sector — isn't that just a bug?"

It's the intended behaviour, stated explicitly in ADR-0001: "A UAV beyond sensing range with no peer message will not know about a far urgent sector — that is the correct, intended behavior, not a bug." Perfect global awareness is exactly the oracle we removed.
